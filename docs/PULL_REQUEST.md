## Что в PR

Графический интерфейс для личного кабинета учёта оборудования
[inventory.f2c.ru](https://inventory.f2c.ru) и документ, описывающий его
архитектуру. GUI — тонкая веб-оболочка (FastAPI + Jinja2) поверх уже
существующего доменного ядра (`f2c_ops.py` / `f2c_inventory.py`): вся
«умная» логика (candidate trial, авто-refresh токена, recon-карта)
переиспользуется без изменений.

## Изменения

- `docs/GUI_ARCHITECTURE.md` — архитектура и логика GUI: слои
  (представление → домен → транспорт), иерархия L1–L4
  (организация → адрес → инвентаризация → оборудование), управление
  сессией с автообновлением токена при 401, recon-движок, перебор
  кандидатов (candidate trial), модули GUI, ленивая загрузка, dry-run,
  требования (ошибки, маскирование токенов, min-interval);
- `webui/app.py` — веб-приложение: экраны организаций, адресов (живой
  поиск), реестра оборудования, мастер добавления с ленивой загрузкой
  адресов, карточка с вкладками (обзор/действия/фото/серийник/история),
  dry-run предпросмотр, cookie-сессия UI, 401-защита страниц;
- `webui/mock_api.py` — мок-бэкенд, имитирующий реальную схему F2C
  (auth login/refresh, организации → адреса → инвентаризации →
  оборудование, действия карточки) — для локального демо и тестов;
- `webui/sample_api_map.json` — карта эндпоинтов из реального бандла
  пользователя (fallback, если `recon` ещё не выполнялся);
- `webui/templates/`, `webui/static/style.css` — 19 шаблонов и тёмная тема;
- `README.md`, `docs/GUIDE.md`, `f2c_inventory.py` (команда `docs`) —
  ссылки на новый документ и инструкция запуска GUI.

## Как запустить

```bash
pip install -r requirements.txt fastapi "uvicorn[standard]" jinja2 python-multipart

# демо (мок-бэкенд): вход — любой email, пароль "secret"
python3 webui/mock_api.py &
F2C_BASE_URL=http://127.0.0.1:8799 F2C_CONFIG_DIR=/tmp/f2c-gui-config \
python3 -m uvicorn webui.app:app --host 0.0.0.0 --port 8000
# → http://localhost:8000

# против реального кабинета (с машины, где сайт доступен):
F2C_BASE_URL=https://inventory.f2c.ru python3 -m uvicorn webui.app:app --port 8000
```

## Тестирование

- смоук-тест всех экранов и действий через curl (15+ сценариев): вход/
  выход с cookie-сессией, защита страниц (без входа — редирект на /login),
  живой поиск адресов, мастер добавления (dry-run и реальное создание),
  transfer/found/unfound/review, загрузка фото, поиск по серийнику
  (ручной и по фото), история, редактирование, удаление;
- проверено, что маршруты действий подбираются через candidate trial
  (например, found → `/api/equipment/inventories/7/500/found`) и
  отображаются пользователю в flash-сообщении.
