# Руководство по работе с f2c_inventory

Инструмент автоматизирует работу с личным кабинетом учёта оборудования
**inventory.f2c.ru** (F2C). Ниже — что это за система, как устроен
инструмент и типовые сценарии.

## Что такое система

Кабинет ведёт учёт оборудования по структуре:

```
Организация (ГБОУ Школа № 1557, Колледж № 32, …)
 └── Адрес (здание/помещение: город, улица, дом)
      └── Инвентаризация (кампания учёта: активная/завершённая)
           └── Оборудование (карточки: серийник, фото, статус)
```

Основные сущности и их маршруты в интерфейсе (по данным из JS-бандла):

| Раздел интерфейса | Маршрут | Смысл |
|---|---|---|
| Карта | `/cabinet/map` | интерактивная карта адресов |
| Адреса организации | `/organizations/{org}/addresses` | список/поиск адресов |
| Оборудование | `/equipment`, `/cabinet/equipment` | реестр карточек |
| Инвентаризации | `/inventories`, `/cabinet/inventories/{id}` | кампании учёта |
| Карточка оборудования | `/equipment/inventories/{inv}/{eq}/…` | действия по карточке |

Действия по карточке в интерфейсе: `found` (найдено), `unfound`
(не найдено), `transfer` (перенос на другой адрес), `review` (осмотр),
`photos` (фото), `serial-lookup/manual` и `serial-lookup/photo` (поиск
оборудования по серийному номеру — вручную или распознавание по фото).

## Как инструмент понимает API

У системы нет публичной документации API, поэтому инструмент опирается на
**карту эндпоинтов** (`~/.config/f2c-inventory/api_map.json`), которую можно
получить двумя способами:

1. `python3 f2c_inventory.py recon` — скачивает JS-бандлы сайта и извлекает
   пути из кода (у вас это уже сделано — найдено ~100 путей);
2. `python3 f2c_inventory.py recon --har chrome-net-export-log.json` —
   точнее: анализ реального сетевого лога браузера (методы, поля,
   авторизация).

В карте многие пути имеют метод `?` (в бандле не видно метода). Поэтому
команды `addr`/`equipment`/`card` используют умные умолчания и **перебирают
кандидатов**: сначала пути из карты, затем типовые REST-пути вида
`/api/equipment/{id}/transfer`. Первый отвечающий эндпоинт побеждает
(404/NOT_FOUND/HTML пропускаются).

Если API у вас отличается — любой вызов можно уточнить вручную:

```bash
python3 f2c_inventory.py card 42 transfer --path /api/equipment/42/move \
    --method POST -d '{"to_address_id": 15}'
```

## Авторизация

- `login` — вход по рабочей почте и паролю. Инструмент сам находит эндпоинт
  входа (`/api/auth/login` по карте), сохраняет access- и refresh-токены
  в `~/.config/f2c-inventory/session.json` (права 600).
- При получении 401 инструмент автоматически обновляет токен через
  `/api/auth/refresh` и повторяет запрос — удобно для cron/watch.
- `status` — проверить сессию; `logout` — стереть её.

## Общий обзор команд

| Команда | Назначение |
|---|---|
| `recon [--har ФАЙЛ]` | построить карту API |
| `login` / `logout` / `status` | сессия |
| `api-map` / `health` / `call` | отладка API |
| `addr search|list|pick|show` | **интерактивный поиск по адресам** |
| `equipment list|add|show` | **список и добавление оборудования** |
| `card <id> [действие]` | **все операции с карточкой** |
| `list/get/create/update/delete/export/import/watch` | универсальные операции с ресурсами |
| `run script.py` | пользовательские процессы (примеры в `examples/`) |
| `docs` | список документации |

## Безопасность

- Пароль нигде не сохраняется; токены — в файле с правами 600.
- Отчёты по HAR маскируют токены/пароли.
- `--min-interval N` задаёт паузу между запросами (берегите сервер);
  `--dry-run` показывает запрос без отправки.

## Частые проблемы

| Симптом | Решение |
|---|---|
| `[err] NOT_FOUND: Не удалось найти рабочий эндпоинт…` | снимите HAR (`recon --har`), либо укажите `--path`/`--method` |
| `[err] UNAUTHORIZED: No token` | выполните `login` |
| Сетевая ошибка TLS | `pip install curl_cffi` (клиент переключится на эмуляцию Chrome) или `--proxy` |
| Поле в запросе не принимается | уточните тело через `-d '{"точное_поле": …}'` |
