# analyzer.sh — мобильный аудит веб-ресурсов (Termux)

Интерактивный Bash-скрипт для быстрого технического аудита веб-страниц прямо
с Android-устройства в среде [Termux](https://termux.dev).

Скрипт собирает метрики производительности (DNS, TCP, TLS, TTFB), анализирует
HTTP-заголовки и базовое содержимое страницы, сохраняет результат в
структурированный JSON-отчёт и умеет загружать HTML-копию страницы в
GitHub Gist. Работает в двух режимах:

* **GUI-режим** (по умолчанию, без аргументов) — ввод URL и подтверждение
  загрузки на Gist через диалоги `termux-dialog` (пакет Termux:API);
* **CLI/headless-режим** (URL передаётся аргументом) — для автоматизации:
  Tasker, cron, другие скрипты.

---

## Возможности

* Сбор метрик фаз соединения одним запросом `curl` (`-w`):
  * `dns_resolution` — DNS-резолв;
  * `tcp_connection` — установление TCP-соединения;
  * `tls_handshake` — TLS-рукопожатие (для HTTPS);
  * `ttfb` — время до первого байта;
  * `total` — общее время.
* Анализ HTTP-заголовков: HTTP-код, `Content-Type`, `Server`,
  `Strict-Transport-Security` (разбор `max-age`, `includeSubDomains`, `preload`),
  `Content-Length`, признак сжатия тела.
* Извлечение и декодирование HTML-тега `<title>` (включая многострочные теги
  и HTML-сущности; декодирование через Python 3 при его наличии).
* JSON-отчёт (генерируется через `jq`, при его отсутствии — вручную
  с валидацией через `python3 -m json.tool`).
* Загрузка HTML-копии страницы в GitHub Gist (secret по умолчанию,
  публичный — с опцией `--gist-public`).
* Автодополнение схемы (`example.com` → `https://example.com`),
  поддержка IDN (конвертация в punycode выполняется `curl`'ом) и IPv6
  (голые адреса вида `2001:db8::1` автоматически заключаются в скобки).
* Повторы запроса при transient-ошибках (curl exit code 6, 7, 28, 35 —
  до 2 повторов с задержкой 1 с).
* Системные уведомления Termux с уникальным `--id` (отключаются опцией
  `--no-notification`).
* Ротация журнала `error.log` при превышении 1 МБ.
* **Проверка зависимостей с автоподготовкой**: скрипт проверяет наличие
  утилит и в интерактивном режиме предлагает установить недостающие пакеты
  через `pkg` (в headless-режиме при отсутствии обязательных зависимостей —
  выход с кодом 2, как требует ТЗ).
* **Режим отладки** `--debug`/`-d`: трассировка команд (`set -x`) и
  лог ошибок с номером строки (`Ошибка в строке N. Код возврата: M`).
* **Структурированный цветной вывод**: теги `[*]` (шаг), `[+]` (успех),
  `[!]` (предупреждение), `[-]` (ошибка), `[i]` (метрика); таблица метрик
  соединения и красивый JSON-отчёт (`jq -C`). Цвета автоматически
  отключаются при выводе не в терминал (или при `NO_COLOR=1`).

## Требования

* **ОС:** Android 8.0+;
* **Termux** — последняя стабильная версия (F-Droid или GitHub);
* **Bash ≥ 4.0**;
* **curl ≥ 7.68** (рекомендуется; проверяется с предупреждением);
* GNU **grep**, **sed**;
* **jq** — рекомендуется (без него JSON собирается вручную);
* **termux-api** (`termux-notification`, `termux-dialog`) — для GUI-режима
  и уведомлений;
* **python3** — опционально (декодирование сущностей, валидация JSON,
  резервная сборка Gist-запроса);
* **coreutils** (`mktemp`, `date`, `stat` и др.).

### Обязательные зависимости

`bash`, `curl`, `grep`, `sed`, `mktemp`, `date`, `head`, `tail`, `tr`, `cut`,
`mkdir`, `mv`, `rm`, `wc`, `basename`, `dirname`. При отсутствии любой из них
скрипт выводит понятное сообщение и завершается с кодом **2**.

## Установка

```sh
# установка зависимостей в Termux
pkg update
pkg install curl coreutils grep sed jq termux-api python

# скачивание скрипта (или скопируйте analyzer.sh на устройство любым способом)
curl -L -o analyzer.sh https://<ваш-хостинг>/analyzer.sh

chmod +x analyzer.sh
```

Если какие-то утилиты не установлены, скрипт при запуске сообщит об этом и
в интерактивном режиме предложит установить недостающие пакеты:

```
[*] Проверка зависимостей...
[!] Отсутствуют необязательные: jq (функциональность будет урезана)
Установить их сейчас? (pkg install -y jq) (y/n): y
```

## Настройка GitHub токена

Для загрузки HTML-копии на Gist нужен Personal Access Token (classic или
fine-grained) **с правом `gist`**:

1. Откройте https://github.com/settings/tokens.
2. Generate new token:
   * classic: поставьте галочку **`gist`**;
   * fine-grained: выберите репозиторий, в разделе *Account permissions*
     → *Gists* → **Access: Read and write**.
3. Скопируйте токен и задайте его переменной окружения:

```sh
export GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

В GUI-режиме, если переменная не задана, токен запросится через диалог
(`termux-dialog password`). В CLI-режиме без токена попытка загрузки на Gist
завершится с кодом **5**.

Токен нигде не сохраняется: не пишется в файлы, не логируется и не выводится
на экран.

## Использование

### GUI-режим (по умолчанию)

```sh
./analyzer.sh
```

Последовательность шагов:

1. диалог `termux-dialog text` — ввод URL (отмена = выход с кодом 0);
2. во время запроса — уведомление с уникальным `--id`;
3. по завершении — уведомление об успехе/ошибке и сводка в терминале;
4. вопрос «Загрузить на Gist?» (`termux-dialog confirm`);
5. при согласии — запрос токена, если `GITHUB_TOKEN` не задан.

Если `termux-api` не установлен, скрипт переходит в упрощённый текстовый режим
(`read -p` для URL и `read -r -p "Загрузить на Gist? [y/N]"` для подтверждения)
и пишет предупреждение в `error.log`.

### CLI/headless-режим

```sh
./analyzer.sh https://example.com
./analyzer.sh --url example.com -o ~/audit --follow-redirects
./analyzer.sh example.com --gist --json-only
GITHUB_TOKEN=ghp_xxx ./analyzer.sh example.com --gist-public
```

В CLI-режиме уведомления Termux включены по умолчанию (отключить —
`--no-notification`).

### Интеграция с Tasker

Пример задачи (Tasker → *Code / Shell* или через плагин Termux:Tasker):

```
./analyzer.sh https://example.com --gist --json-only --no-notification > /sdcard/audit.json
```

Код возврата скрипта можно проверять как условие задачи
(0 — успех, 4 — сетевая ошибка, 5 — ошибка GitHub API и т.д.).

### Опции

| Опция | Описание |
|---|---|
| `-u, --url <url>` | URL для анализа (или позиционный аргумент) |
| `-t, --timeout <сек>` | Общий таймаут запроса (по умолчанию 30) |
| `--connect-timeout <сек>` | Таймаут установления соединения (по умолчанию 10) |
| `-d, --debug` | Режим отладки: трассировка команд (`set -x`) и лог ошибок с номером строки |
| `-o, --output-dir <путь>` | Каталог для сохранения файлов (по умолчанию текущий) |
| `--json-only` | Вывести только JSON-отчёт в stdout (без сообщений); файлы не сохраняются, если не задан `--output-dir` |
| `--no-notification` | Отключить системные уведомления |
| `--gist` | Автоматически загрузить HTML-копию на Gist (требуется `GITHUB_TOKEN`) |
| `--gist-public` | Создать публичный Gist (по умолчанию secret) |
| `--max-size <байт>` | Максимальный размер загружаемого тела (по умолчанию 10 МБ; `0` — без ограничения) |
| `--follow-redirects` | Следовать HTTP-редиректам (до 5); метрики относятся к финальному ответу |
| `-h, --help` | Справка |
| `--version` | Версия скрипта |

### Коды возврата

| Код | Значение |
|---|---|
| 0 | Успешное завершение |
| 1 | Общая ошибка (непредвиденная) |
| 2 | Отсутствуют обязательные зависимости |
| 3 | Невалидный URL или запрещённая схема |
| 4 | Сетевая ошибка или таймаут (в т.ч. превышение `--max-size`) |
| 5 | Ошибка при обращении к GitHub API |
| 6 | Ошибка генерации/сохранения отчёта |

## JSON-отчёт

Отчёт сохраняется как `report_YYYYMMDD_HHMMSS_PID.json` (права **600**).
Схема (обязательные поля):

```json
{
  "url": "https://example.com",
  "timestamp": "2026-08-19T10:30:00Z",
  "http_code": 200,
  "timings": {
    "dns_resolution": 0.123,
    "tcp_connection": 0.045,
    "tls_handshake": 0.234,
    "ttfb": 0.356,
    "total": 1.234
  },
  "headers": {
    "content_type": "text/html; charset=UTF-8",
    "server": "nginx",
    "strict_transport_security": "max-age=31536000; includeSubDomains",
    "hsts": {
      "max_age": 31536000,
      "include_subdomains": true,
      "preload": false
    },
    "content_length": 12345
  },
  "content": {
    "title": "Example Domain",
    "size_bytes": 12345,
    "size_transferred": 12345,
    "compressed": false
  },
  "redirects": {
    "followed": false,
    "count": 0,
    "final_url": "https://example.com"
  },
  "file_paths": {
    "html": "/data/data/com.termux/files/home/audit/page_20260819_103000_1234.html",
    "headers": "/data/data/com.termux/files/home/audit/headers_20260819_103000_1234.txt",
    "report": "/data/data/com.termux/files/home/audit/report_20260819_103000_1234.json"
  },
  "gist_url": null,
  "status": "success",
  "error": null
}
```

Пояснения:

* `status`: `success` (HTTP 2xx), `partial` (HTTP 4xx/5xx — анализ выполнен),
  `error` (сетевая ошибка, превышение лимита размера и т.п.);
* `error` — описание ошибки или `null`;
* `timings` — секунды, округлены до трёх знаков после запятой;
* `content.size_bytes` — фактический размер сохранённого файла
  (для сжатого ответа — декодированного), `size_transferred` — размер тела
  по данным curl (переданный, сжатый); `compressed` — было ли применено
  Content-Encoding;
* `headers.hsts` — разобранные атрибуты `Strict-Transport-Security`
  (дополнительное поле к полной строке `strict_transport_security`);
* `file_paths.*` — `null`, если артефакты не сохранялись (`--json-only`
  без `--output-dir`);
* `gist_url` — ссылка на созданный Gist или `null`.

`hsts` и `content.size_transferred` — расширения базовой схемы; остальные
поля строго соответствуют ТЗ.

## Логирование

Журнал пишется в `error.log` в рабочем каталоге (или в `--output-dir`).
Формат строки:

```
[2026-08-19 10:30:00] INFO: Начало аудита: https://example.com
```

Уровни: `INFO`, `WARNING`, `ERROR`. Логируются начало/завершение аудита,
ошибки сети (с кодом возврата curl), отсутствие необязательных зависимостей,
проблемы GitHub API. **Не логируются** токены, пароли и полные URL
с query-параметрами (только домен и путь; учётные данные в URL маскируются).
При превышении 1 МБ журнал переименовывается в `error.log.1`.

## Сохраняемые файлы

В каталог `--output-dir` (по умолчанию `$PWD`) сохраняются:

| Файл | Права | Назначение |
|---|---|---|
| `page_YYYYMMDD_HHMMSS_PID.html` | 644 | HTML-копия страницы |
| `headers_YYYYMMDD_HHMMSS_PID.txt` | 600 | HTTP-заголовки |
| `report_YYYYMMDD_HHMMSS_PID.json` | 600 | JSON-отчёт |

Суффикс `PID` обеспечивает уникальность имён при параллельных запусках.

## Безопасность

* Весь пользовательский ввод (URL, пути, токены) передаётся в команды
  исключительно через массивы аргументов — без `eval` и конкатенации
  в строку команды.
* Разрешены только схемы `http`/`https`; `file://`, `ftp://`, `javascript:`
  и другие отклоняются с кодом 3. При `--follow-redirects` curl дополнительно
  ограничивается `--proto-redir '=http,https'`.
* Из URL удаляются управляющие символы; пробелы считаются ошибкой валидации.
* Отчёты и заголовки имеют права 600; токены не сохраняются и не логируются.
* При `--max-size` загрузка прерывается через `curl --max-filesize`.

## Ограничения и замечания

* Повторы запроса реализованы вручную (до 2 повторов при curl exit code
  6/7/28/35 с задержкой 1 с), а не через встроенный `--retry` curl, чтобы
  точно соответствовать разделу 2.7 ТЗ и не создавать двойных повторов.
* Без `jq` и `python3` декодирование HTML-сущностей и полное экранирование
  JSON ограничены (обрабатываются основные сущности; управляющие символы
  заменяются). Установите `jq` и `python3` для полной функциональности.
* Для загрузки на Gist без `jq` требуется `python3`.
* Проверка версии curl носит предупредительный характер: критично только
  наличие curl.

## Тестирование

```sh
./tests/run_tests.sh
```

Тестовый набор поднимает локальный HTTP-сервер (Python 3) и прогоняет
тест-кейсы раздела 4 ТЗ: валидный URL, автодополнение схемы, невалидный URL,
запрещённые схемы, таймаут, HTTP 404/500, отсутствие `<title>`/HSTS,
GUI без termux-api, Gist без токена и с неверным токеном, превышение
`--max-size`, параллельные запуски, SIGINT/SIGTERM, отсутствие `jq`,
а также редиректы, сущности, UTF-8, сжатие, `--json-only`, IPv6 и
реальный HTTPS-аудит. Требуются `python3`, `jq`, `curl`, `bash`.

Для самопроверки стиля используется ShellCheck:

```sh
shellcheck analyzer.sh        # без предупреждений
```
